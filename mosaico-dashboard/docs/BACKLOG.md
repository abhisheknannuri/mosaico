# Mosaico Dashboard: Backlog

> Single source of truth for **what we build next**. Work top to bottom, **one task at a time**.
> The big-picture "why" lives in `../../DASHBOARD_BUILD_PLAN.md`; decisions live in `decisions/`.

## How we work

1. Pick the **first task with status `todo`**. Don't start the next one until the current one is `done`.
2. Branch from `AN/FastAPI_Dashboard` as `dash/<ID>-short-name` (or work directly on the
   branch, but **one commit per task**).
3. Commit message follows the repo's Conventional Commits rule (`CONTRIBUTING.md`), scoped to the
   dashboard: `feat(dashboard): D-05 app factory and /healthz`, `docs(dashboard): …`,
   `chore(dashboard): …`, `test(dashboard): …`.
4. When done: tick the acceptance criteria, set status `done`, add one line to `DEVLOG.md`, and
   write/update an ADR in `decisions/` **if the task made a decision**.
5. If a task turns out bigger than ~1 day, **split it** here before continuing.

Status values: `todo` · `doing` · `done` · `dropped` (with a reason).

### Definition of Done (applies to every task)

- [ ] Code is formatted and linted: `ruff format --check . && ruff check .` (same rules as the SDK).
- [ ] Type check passes: `pyright` (from task D-02 onward).
- [ ] Tests for the new behaviour exist and pass: `pytest` (from D-02 onward).
- [ ] No secrets in code, logs, templates or git.
- [ ] Nothing outside `mosaico-dashboard/` is modified (exception: tasks explicitly marked **upstream**).
- [ ] Docs touched where relevant (README, `architecture.md`, ADR, `DEVLOG.md`).
